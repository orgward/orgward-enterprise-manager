## Context, trace coverage and guarded change

Context manifests bind change/system IDs, accepted baseline, Sentinel snapshot and
its input baseline/profile/compiler, policy/authority versions, requirement/risk/
obligation/assumption references, retrieval manifest, coverage and excluded/unknown
dependencies. Pin immutable bytes and typed scoped revision references, not a URL
to mutable latest. Record inclusion/exclusion reasons, source cursors and evidence
classification. An optional explicitly unknown analytics integration can remain
unknown; an unknown mandatory property authority blocks runnable planning.

Retrieval must pass current read authorization before inclusion. Denied data is
neither absent nor safe to summarize through another model. Error messages must
not reveal hidden object labels/counts. Token limits require deterministic coverage
accounting: retain mandatory constraints verbatim as typed inputs or stop with a
context-capacity blocker. Chunking creates a manifest of all required chunks and
their dependencies; a successful model response cannot prove complete coverage.

At accepted policy/authority publication, invalidate dependent requirement
applicability, evaluations and approvals in the authoritative transaction. Keep
old immutable requirements/results; stale means unusable for the changed target,
not deletion of the original truth. A broker racing delayed projections must deny
the old tuple under the new generation. Historical reconstruction resolves pinned
bytes where retention permits; it does not promise byte-identical fresh LLM output,
revive old grants or promise retained data beyond lawful disposal constraints.

Requirements are independently identifiable obligations with outcome, source,
scope, risk, acceptance method and applicability. Tests assert observable behavior
through API/storage/provider evidence; copying the requirement sentence to output
must fail the deliberately broken control. Keep the accepted suite inventory and
mandatory criterion IDs outside the candidate branch's unilateral control. Test
deletion or weaker thresholds require explicit reviewed change and cannot erase
a previously failed mandatory obligation from assurance.

Mandatory criteria are conjunctive eligibility conditions, not a weighted average.
Unknown, failed and stale remain distinct. Review records conflict and corrective
work; it cannot score away immutable denies. Nonmandatory tradeoffs require an
explicit applicable policy, rationale and evidence. New observations propose
claims/design corrections; they never promote observed bypass into accepted authority.

## Multi-repository and human-owned change

A coordinated release manifest identifies each provider/repository, immutable base
and candidate commit, owned branch, dependency lock/build recipe/toolchain, required
checks, artifact digests, interface/schema versions, environment and release order.
Names such as service-base-a are fixture aliases only: materialized seeds require
actual provider identities, commit hashes and verified bytes. Include transitive
dependencies and build inputs, not just direct package version strings.

Use expand → compatible producer → compatible consumer → contract. Qualification
must enumerate old/new producer/consumer/schema combinations at each permitted
transition, including rollback. Remove a field only after consumers are migrated
and no retained active-run/recovery requirement needs it. Backfill is checkpointed,
reconciled and idempotent; destructive migration needs a reviewed data-preserving
recovery design. Source head drift or changed dependency bytes invalidates the
bound candidate; no silent rebase under a previous approval.

Repository operations are independent durable effects, not a distributed atomic
commit. Save provider operation identities and reconcile merge/build state before
retry. One merged repository plus another failed repository is partial work, not
release success. An explicit new correction can change only the failed repository
if compatibility and current review allow; retain the original service receipt.
Compensating commits need their own authorization and checks. Failed builds may
retry reproducible computation under the approved attempt policy; unknown merges
cannot be blindly repeated as though they were computation.

Architecture alternatives compare the same context: business fit, data/authority,
failure modes, fitness evidence, cost units/workload assumptions and reversal.
Label estimates separately from measured results. Acceptance records the selected
alternative and rationale plus rejected options; no automatic cheapest-wins rule.

Regeneration stages new artifacts in isolated attempts. A three-way merge uses
base, current human branch and generated candidate with typed model-field/path
ownership. Preserve human edits even when a generated file replaces a whole file;
unknown ownership conflicts rather than guessing. Resolved content has a new digest
and fresh assurance. Cancel/provider failure cannot publish partial architecture
or overwrite the user's branch. Partial artifacts stay restricted attempt evidence;
uncertain usage remains reconciliatory. Accepted architecture deltas update Studio
system/refinement objects through CP-01–CP-03, never direct second-store writes.

## Promotion, operations and incident feedback

Promotion binds candidate/build/signature/check/context/policy/config/environment
and target identity. Server checks current trust and authorizations at dispatch.
Environment labels are not target identities. Secrets are references resolved by
the broker; stored manifests and UI never contain their values. Running digest
and effective nonsecret configuration are independently read back from the target.

The AC1 profile uses a full 300-second health/control window, fixed before running.
Specify sample cadence, completeness and mandatory signal predicates in the seed;
missing intervals are unknown, not healthy. Production profiles may choose other
reviewed windows but cannot shorten them after a failure. Technical acceptance
requires all mandatory controls for the entire configured window, not a deploy ACK.

Lost response after accepted deployment means reconcile by provider operation and
actual target state. A failed canary stops further promotion; rollback requires
current eligible approval and T-92 compatibility evidence, then its own observation
window. No automatic data restore after new writes. Preserve original failure and
rollback separately. When safe rollback is unavailable, remain recovery-required
with owned forward recovery instead of falsely restoring a green release label.

Business acceptance pins metric formula, target, population, data source, window
and coverage independently from technical health. Missing observations mean unknown;
technical pass and unknown business outcome must be visible simultaneously in
Studio/SDLC/readiness. Correction feedback binds incident → actual deployment →
process/property/system → proposed change → reviewed baseline → new context/eval →
subsequent measurement. Zero unauthorized source reads in a complete observed window
supports that scoped target only; an incomplete window cannot prove zero.

Deduplicate exact source event identity and bytes, not merely symptom text. The
same symptom after rollback with new evidence is a distinct linked recurrence.
Retain old decisions and causal links. Automated fixes remain proposals unless
separately authorized; they cannot grant themselves approval or recycle stale proof.

## Business effects and connector lifecycle

Use the same effect broker for SDLC deployment and business-service actions.
The AC1 service fixture has capacity 3, reserves 2 and consumes exactly 2 on
confirmed fulfilment, leaving 1 available; materialize the unit/calendar/scope and
commitment revision. Reserve atomically, check capacity and current commitment at
dispatch, and retain reservation through unknown outcome. Timeout does not release
capacity for another actor to oversubscribe. Physical completion needs qualified
adapter evidence or explicitly identified human attestation, not a generated label.

Partial effects keep individual states/receipts. Compensation is a separate action
with its own scope, permission, policy, budget and relation to original effect.
Issue then cancel a test ticket remains two events; it is not erasure or an atomic
rollback. Some costs/physical acts cannot be reversed: retain residual obligation,
owner and business resolution. Live payment/legal/physical permission is never
inferred from a generated process, connection activation or this specification.

Required adapter classes inherit QUALIFICATION: identity, secrets, artifact storage,
SCM, model and isolated deployment; this operating slice additionally requires an
isolated business-service adapter. PostgreSQL and Temporal are required services,
not an excuse to omit the provider/adapter inventory. Pin exact versions only in
tested implementation release locks. Each supported manifest records capabilities,
reads/effects/events, schemas, minimum provider scopes, authentication/reference
rotation, retention/classification/residency, rate limits, idempotency/reconciliation
and disable behavior. Connectivity alone does not qualify an effect adapter.

Ingress verifies authenticity on original bytes under the provider's pinned profile,
source/tenant binding, replay window and schema before admission. A duplicate valid
event with identical bytes is acknowledged without a second logical event; same ID
with different bytes is quarantined as a conflict. Invalid signature cannot advance
the cursor or create accepted state. Webhooks and backfill share source identity/
revision deduplication. Persist admitted inbox rows/checkpoint together before ACK;
only contiguous accounted-for progress advances the cursor. Quarantine is durable,
owned and restricted, not discarded work. An invalid event is not marked processed.

Retry obeys finite attempts and elapsed time, provider retry-after and cancellation.
The fixture uses three attempts/60 seconds; if retry-after exceeds the remaining
budget, pause/escalate instead of exceeding the bound. Jitter is recorded/seeded for
tests, not a semantic oracle. Cursor expiry requires controlled overlap/backfill and
exact source reconciliation. Credential rotation rechecks scope; no widening or
continued use of revoked credentials. If current remote status cannot be obtained,
retain unknown work rather than manufacturing successful reconciliation.

Disable preview lists active consumers, queued and accepted effects, retained data
and authority changes. Revoke normal work/access immediately, including downloads,
search and retrieval; separately authorized narrow reconciliation may finish accepted
effects. Never preserve an old broad grant to make drain easy. Final disable can
wait on owned recovery and retention constraints; it does not mean cached data erased.
